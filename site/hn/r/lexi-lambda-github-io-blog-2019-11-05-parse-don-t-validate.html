  • I often practice test driven development . This can help, especially in dynamic languages, to structure your code in a way that forces you to keep it simple. 1. Write the test first, start with the smallest cases. 2. Write the code to make the test pass, the first thing that comes to mind which works. 3. Refactor what you just wrote. Use functions to remove unnecessary intermediate variables, avoid repetitive code by extracting common patterns, turn literals into parameters constants, etc. 4. Add another test, usually an inductive step. If your base case, smallest input is n , try writing a test that should pass for n+1 . 5. Repeat 2-3 until the new test passes. 6. Add the smallest edge case
